Stable Codec

Stable Codec 把低码率 speech codec 往 Transformer 化推进，用 FSQ 做离散瓶颈。它的重点是稳定、低码率、可建模的语音前端，而不是单纯追求更复杂的 RVQ 层级。

Paper Deep Dive

论文精讲：Stable Codec 如何用 Transformer 和 FSQ 稳住低码率

模型解析Transformer 编解码器夹住 FSQ 离散瓶颈
  • 输入语音先进入 Transformer encoder，利用自注意力建模长上下文和韵律信息。
  • FSQ bottleneck 把连续 latent 映射成有限标量离散码，减少传统 VQ 的 codebook 不稳定问题。
  • Transformer decoder 再结合位置编码和上采样恢复语音。
创新点稳定性优先，而不是只堆码本
  • FSQ 用固定离散格点替代学习式码本，降低 codebook collapse 和索引利用不均的问题。
  • Transformer 主干增强长程建模，对低码率下的韵律和说话人特征更重要。
  • 可选 residual refinement 在质量预算允许时继续补残差。
损失函数低码率语音要同时约束清晰度和自然度
  • 重建损失负责语音内容、能量和频谱形状。
  • 感知或对抗类目标用于减少低码率下常见的金属感、糊感和过平滑。
  • FSQ 不依赖传统 codebook commitment，但仍需要约束离散 token 与 decoder 的可解码匹配。
训练策略先稳定主瓶颈，再加残差精炼
  • Transformer encoder / decoder 和 FSQ 主链路先学会低码率重建。
  • 可选低阶残差分解在主 token 基础上补充细节，而不是替代主瓶颈。
  • 训练重点是让 token 分布稳定，方便后续生成模型或通信系统使用。
结果分析适合低码率 speech codec 和 token prior
  • FSQ token 更规则，通常更利于下游模型学习分布。
  • Transformer 长上下文让低码率下的语音连续性更好。
  • 代价是推理结构可能比纯卷积 codec 更重，实时部署要看具体配置。
Core Route

Stable Codec 的路线取向

01Transformer 化

声学恢复不再只靠卷积局部结构，也引入更强时序建模。

02FSQ 做瓶颈

固定标量量化降低 codebook 训练不稳定性。

03极低码率导向

目标更接近语音通信和 spoken LM 前端约束。

04稳定性优先

名字里的 stable 更像系统指标：训练稳、表示稳、恢复稳。
