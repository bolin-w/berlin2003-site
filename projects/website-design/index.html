网站设计

从页面结构、前端样式到 Caddy 部署与 Notion 集成，记录这个网站具体怎么做出来的每一步。

模块一

页面结构与路由

站点由多个独立页面组成，每个页面有对应的职责。Caddy 把 URL 路径映射到 /var/www/personal-site/ 下的目录，公共页面直接走 file_server，私密页面加 basicauth。

  • /research/ — 研究地图，语义与声学两条主线
  • /projects/ — 项目总览，三个方向各领子页
  • /notes/ — 笔记聚合，Notion 文章按分类展示
  • /anime/ — 视频放映室，本地字幕片库
  • /studio/ — 后台工作台（需登录），Notion 导入入口
  • /life/ — 私密日记页（需登录）

模块二

Section-Lab 设计系统

全站公共页面共用一套 CSS 变量与组件，保证视觉一致。两个核心样式表分工明确：

  • style.css — 基础 reset、字体、变量定义、老版 edition-body 样式
  • section-lab.css — section-lab 体系的全部组件：topbar、hero、card、panel、grid、links、stats、footer，以及响应式断点（980px / 680px）

关键变量：--section-ink、--section-blue、--section-teal、--section-coral、--section-line、--section-panel、--section-shadow。所有颜色、间距、圆角都从这里取值，改一处即全局生效。

模块三

Notion 笔记集成

把 Notion 页面导入网站，作为笔记和项目文章的来源。后端 API 处理拉取与存储，前端 JS 按分类动态渲染。

  • POST /api/notion/import — 输入 Notion 页面链接 + 分类 + 是否公开，拉取内容落库
  • GET /api/notion/articles — 文章列表，?public=true 过滤公开文章
  • GET /api/notion/articles/:id — 文章详情，返回标题、HTML 内容、分类、时间
  • DELETE /api/notion/articles/:id — 删除文章（需登录）

需在 Notion 页面手动连接 Integration 才能导入，API Key 配置在服务器环境变量中。

模块四

Caddy 反向代理与路由

所有请求先经过 Caddy，再分流到静态文件或后端 API。

  • 公共页面（research、projects、notes、anime、contact）直接 file_server
  • 私密页面（studio、life）加 basicauth，密码哈希用 bcrypt
  • 公开 API（文章列表等）直接反向代理到后端
  • 写入类 API（导入、删除等）需 basicauth 后再代理
  • 视频流单独走媒体代理路径，不经过主后端
  • 启用 zstd + gzip 压缩，安全头（X-Content-Type-Options、X-Frame-Options、Referrer-Policy）

模块五

部署流程

本地改完文件后，通过 SCP 上传到服务器临时目录，再 SSH 进去拷贝到目标位置。没有 CI/CD，手动但可控。

  • SSH 密钥认证，不用密码登录
  • 先 scp 到服务器 /tmp，再 sudo cp 到 web 目录
  • 最后 chown 到 www-data，确保 Caddy 有权限读取
  • 本地保留源码目录和部署快照两个副本

修改 CSS 或 JS 后需更新 HTML 里的 ?v=版本号，否则浏览器可能读缓存。

模块六

前端脚本与动态加载

静态 HTML 负责结构，JS 负责从 API 拉数据并渲染。各页面有独立的 feed 脚本：

  • notes-feed.js — 笔记页，按分类（论文阅读、模型判断、部署记录等）分组展示 Notion 文章
  • project-page.js — 项目子页，读取 data-match 关键词过滤对应文章
  • article-detail.js — 文章详情页，根据 URL 的 ?id 参数加载文章内容
  • site-chat.js — 全站 AI 聊天按钮
  • notion-import.js — 后台导入页，处理表单提交与文章列表管理

所有脚本通过 ?v=版本号 参数控制浏览器缓存。修改 CSS 或 JS 后更新版本号即可强制刷新。
